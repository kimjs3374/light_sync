# Light-Sync 생산관리(Production Management) 모듈 개발 명세

## 1. 모듈 개요 및 핵심 워크플로우
* **자동 생성 로직:** '영업관리'에서 계약(현장) 및 품목이 생성될 때, 생산 DB에도 해당 품목의 '생산 공정 데이터'가 자동으로 생성되어야 합니다.
* **UI/UX 기준:** 기본 div 구조, 정렬(Sort) 규칙, 리스트 뷰 형태는 '계약관리' 메뉴의 스타일과 100% 동일하게 구성하세요. 최상위는 '계약(현장)' 단위이며, 하위로 '품목'이 펼쳐지는 **트리 구조**입니다.
* **공통 기능 (히스토리보드):** 기존에 구현된 통합 히스토리보드를 이 화면에도 공통 컴포넌트로 배치하여, 생산 상태 변경 시 로그가 남도록 연동하세요.

## 2. 생산 상태 (Status) 및 파이프라인 로직
생산 상태는 아래의 4단계로 관리되며, 명확한 상태 변경 트리거를 가집니다.

1. **`자재대기중` (초기 상태):** 해당 품목의 자재 입고가 모두 완료되지 않은 상태.
2. **`생산대기중`:** 자재관리 모듈에서 해당 품목의 모든 필수 자재 상태가 '입고완료'로 변경되면, 생산 모듈의 상태가 자동으로 `생산대기중`으로 변경되어야 합니다.
3. **`생산중`:** 품목별 생산 공정 중 1개 항목이라도 진행 처리가 시작된 경우.
4. **`생산완료`:** 모든 공정이 마지막 단계까지 완료되고 출고를 대기하는 상태.

## 3. 공정(Process) 진행 및 공정률 관리 지침
* **선행 공정 필수:** 각 공정은 단계별(Step)로 이루어지며, 상위(이전) 공정이 완료(또는 진행)되지 않으면 다음 공정으로 넘어갈 수 없도록 프론트엔드 UI(비활성화 처리) 및 백엔드 검증 로직을 구현하세요.
* **일일 진행량 및 공정률 파악:**
  * 각 공정 항목별로 '일일 진행량(수량)'을 기입할 수 있는 입력 필드나 모달을 제공하세요.
  * 입력된 데이터를 바탕으로 전체 대비 '공정률(%)'을 계산하여 UI에 참고용(Reference)으로 표시합니다.
  * **주의:** 일일 진행량 입력과 공정률 달성은 강제(Blocker) 사항이 아닙니다. 숫자가 100%가 아니더라도 관리자가 다음 공정으로 강제 진행할 수 있도록 유연하게 설계하세요.

## 4. 품목 및 모델별 상세 공정 명세 (조건부 분기)
해당 품목에 맞춰 아래의 공정 리스트가 DB에 세팅되어야 합니다.

**① 투광등기구**
* **조건부 추가 (일체형):** 속성이 '일체형'인 경우, `브라켓 조립` 공정 바로 직전(Before) 단계에 **`SMPS 일체형 조립`** 공정을 동적으로 추가하세요.
* **모델별 공정 리스트:**
  * **[STA 모델]**
    1. 외함제작 (하위 프로세스: 1-1. 하우징 히트파이프 조립 -> 1-2. 조립부 실리콘작업 -> 1-3. 방열핀 적층 프레스작업 -> 1-4. 후면 커버 조립)
    2. PCB 조립
    3. 렌즈부 조립 (실리콘렌즈 등)
    4. 전면유리커버 조립
    5. 전면 바이저 조립
    6. 브라켓 조립
    7. 포장 및 출고 대기
  * **[ARENA 모델]**
    1. 히트파이프 조립 -> 2. PCB 조립 -> 3. 렌즈부 조립 -> 4. 반사판 조립 -> 5. 전면유리 조립 -> 6. 브라켓 조립 -> 7. 포장 및 출고 대기
  * **[BATOO 모델]**
    1. PCB 조립 -> 2. 렌즈 조립 -> 3. 전면 유리조립 -> 4. 브라켓 조립 -> 5. 포장 및 출고 대기

**② 가로등기구, 보안등기구**
* **조건부 추가 (일체형):** 속성이 '일체형'인 경우, `전선 연결` 공정 직전(Before) 단계에 **`SMPS 일체형 조립`** 공정을 추가하세요.
* **기본 공정:** 1. 모듈 조립 -> 2. 모듈과 분배기 결선 -> 3. 전선연결 -> 4. 포장 및 출고 대기

**③ 스텐가로등주**
* **조건부 제외 (특정 모델):** 모델명이 `MTPS-202-4`, `MTPS-202-5`, `MTPS-202-6`, `MTPS-203-4`, `MTPS-203-5`, `MTPS-203-6` 중 하나일 경우, **`3. 2단폴 용접` 공정을 목록에서 제외(Skip)하세요.**
* **기본/조건부 공정:**
  1. 파이프 재단 및 가공 -> 2. 베이스 및 점검구 용접 -> 3. 2단폴 용접 -> 4. 암대 용접
  5. **조건 분기:** 속성이 '광택'이면 `5. 광택작업`, '도장'이면 `5. 도장입고`로 분기
  6. 출고대기

**④ 철제가로등주**
* **기본/조건부 공정:**
  1. 파이프 재단 및 가공 -> 2. 베이스 및 점검구 용접 -> 3. 2단폴 용접 -> 4. 암대 용접 -> 5. 도금 입고
  6. **조건 분기:** 속성이 '도장(True)'인 경우 `6. 샌딩 작업` -> `7. 도장 입고` -> `8. 출고 대기` / '도장(False)'인 경우 곧바로 `6. 출고 대기`

**⑤ 조명타워**
* **기본 공정:** 1. 플랜지 가접 -> 2. 플랜지 및 보강대 용접 -> 3. 상부구조물 제작 -> 4. 도금 입고 -> 5. 출고 대기
* **모델명에 기초앙카가 포함되면:** 1. L앙카 용접 -> 2. 베이스 용접 -> 3. 도금 입고 -> 4. 출고대기

## 5. 백엔드(DB) 설계 제약 및 지시사항
* **테이블 관계:** 공정 관리를 위해 품목(Item)과 1:N 관계를 가지는 `production_processes` 테이블과, 일일 진행량 로깅을 위한 `production_daily_logs` 테이블 구조를 고려하세요.
* **주의사항 (Out of Scope):** 이전 지시와 마찬가지로 DWG 변환이나 복잡한 ERP(BOM 연동) 구축은 절대 구현하지 마세요. 현재는 주어진 공정 스텝의 UI 상태(활성/비활성/완료)와 일일 진행량 텍스트/숫자 저장 기능 구현에 집중하세요.
