# 알림 시스템 — 대기업 ERP 대비 Gap 분석

- **Date**: 2026-04-06
- **비교 대상**: SAP Fiori, Oracle EBS, 더존 iCUBE, 영림원 K-System 알림 체계
- **현재 수준**: 중소기업 실무형 (47명) → 대기업 수준 도달을 위한 보완점 분석

## 1. 즉시 수정 (방치하면 장애)

### 1.1 중복 방지 로직이 실제로 안 먹힘

**현상**: `dedupe_key` 파라미터를 받지만, 실제 비교는 `title` 기준으로만 함.

```python
# notification_engine.py:289
already = db.query(Notification).filter(
    Notification.user_id == user.id,
    Notification.noti_type == noti_type,
    Notification.title == title,        # ← title로만 비교
    Notification.created_at >= today_start,
).first()
```

**위험**: 납기 초과 현장 50건이면 매일 50 × 47명 = **2,350건**씩 쌓임. 같은 현장이 계속 중복 생성됨. 
title이 조금이라도 다르면 (계약명 수정 등) 중복 방지 실패.

**대기업 방식**: 이벤트 고유키(`event_type + entity_id + date`)로 중복 체크.

**수정 방향**: `dedupe_key`를 실제로 사용하도록 변경.

---

### 1.2 DB 인덱스 없음

**현상**: notifications 테이블에 `user_id`, `created_at`, `is_read` 인덱스 없음.

**위험**: 47명 × 하루 50건 × 90일 = **211,500건** 축적 가능. 
피드 API가 매 요청마다 풀스캔하면 대시보드 로딩 느려짐.

**대기업 방식**: `(user_id, created_at DESC)` 복합 인덱스 필수.

**수정 방향**: ALTER TABLE로 인덱스 추가.

---

### 1.3 카카오워크 rate limit 무방비

**현상**: 스케줄러가 50건을 순차 발송할 때 아무 대기 없음.

```python
# kakaowork_notifier.py:38
resp = requests.post(..., timeout=10)
# → 다음 건 즉시 발송, 간격 없음
```

**위험**: 카카오워크 API rate limit (보통 100req/min) 초과 시 나머지 알림 유실.

**대기업 방식**: 메시지 큐(Redis/Celery) + 지수 백오프 재시도.

**수정 방향**: 최소한 건당 0.5초 sleep 또는 배치 묶음 발송.

## 2. 단기 보완 (사용성/운영 품질)

### 2.1 알림 모델 필드 부족

**현재 필드**: id, user_id, title, message, noti_type, link, is_read, created_at

**대기업 ERP 필수 필드 대비 누락**:

| 필드 | 용도 | 대기업 | 현재 |
|------|------|--------|------|
| `priority` | 긴급/일반/참고 분류 | ✅ | ❌ |
| `read_at` | 읽은 시각 (SLA 측정) | ✅ | ❌ |
| `ref_type` / `ref_id` | 관련 엔티티 추적 | ✅ | ❌ (link URL만) |
| `sender_id` | 발신자 (시스템/사용자) | ✅ | ❌ |
| `expires_at` | 만료일 (기간 한정 알림) | ✅ | ❌ |

**수정 방향**: priority, read_at 2개만 먼저 추가. 나머지는 필요 시.

---

### 2.2 에스컬레이션 없음

**현상**: 
- D-7 알림 → D-1 알림 → **D-0 (당일) 없음** → 초과 알림
- 알림을 안 읽어도 재알림 없음
- 초과 3일 넘어도 관리자 에스컬레이션 없음

**대기업 방식**: 
- D-7 → D-3 → D-1 → **D-0** → D+1(관리자 CC) → D+3(임원 에스컬레이션)
- 미읽음 알림 N시간 경과 시 재발송

**수정 방향**: D-0 이벤트 추가 + 초과 3일 이상 시 관리자 알림.

---

### 2.3 모바일 드롭다운 깨짐

**현상**: 알림 드롭다운이 `width:340px` 고정. 320px 이하 기기에서 화면 밖으로 넘침.

**수정 방향**: 미디어 쿼리 추가 `@media (max-width:576px) { width:90vw; }`.

---

### 2.4 확인/처리 기능 없음

**현상**: "읽음" 밖에 없음. "확인함", "처리 중", "위임" 같은 액션 없음.

**대기업 방식**: 
- 읽음 → 확인(Acknowledge) → 처리완료(Resolved)
- 위임(Delegate) → 위임받은 사람에게 알림 전달

**수정 방향**: 당장은 불필요 (47명 규모). 100명 넘으면 검토.

---

## 3. 중기 개선 (대기업급 도달)

### 3.1 알림 관리자 대시보드 없음

**현상**: 관리자가 "어떤 알림이 몇 건 발생했고, 읽음률이 몇 %인지" 볼 방법이 없음.

**대기업 방식**:
- 알림 발송 통계 (일별/유형별)
- 읽음률 / 평균 읽기 시간
- 채널별 도달률 (ERP vs 카카오워크)
- 미읽음 알림 현황 (사용자별)

**수정 방향**: `/admin/notification-stats` 관리자 페이지 신규.

---

### 3.2 알림 설정 (개인화) 없음

**현상**: 모든 사용자가 모든 알림을 받음. 끌 수 없음.

**대기업 방식**: 
- noti_type별 ON/OFF
- 채널 선택 (ERP만 / 카카오워크만 / 둘 다)
- 알림 요약 (즉시 / 1시간 묶음 / 일일 요약)

**수정 방향**: 47명 규모에서는 불필요. 인원 증가 시 검토.

---

### 3.3 메시지 큐 없음

**현상**: 알림 생성이 동기적. `notify()` 호출 시 즉시 DB INSERT + 카카오워크 API 호출.

**대기업 방식**: Redis/Celery 비동기 큐 → 알림 워커가 처리.

**수정 방향**: 현재 47명 규모 + 건당 10ms 이하이므로 불필요. 
알림이 초당 100건 이상 발생하면 검토.
