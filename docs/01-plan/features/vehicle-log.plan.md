# Plan: vehicle-log (업무용차량 운행기록부)

## Executive Summary

| 관점 | 내용 |
|------|------|
| Problem | 세법상 별지서식 「업무용승용차 운행기록부」를 직원이 매번 종이/엑셀로 작성 → 분실·누락·필체 문제. PC 회계 제출용 출력도 별도 작업 필요 |
| Solution | 신규 운행일지 메뉴. 모바일에서 운전자가 즉시 등록(주행 후 계기판만 입력하면 자동 계산) → PC에서 월별 조회 + 세법 양식 그대로 엑셀 다운로드해 회계 제출 |
| Function/UX | 모바일: More 메뉴 → 운행일지(폼 1탭, 직전 odometer 자동 채움, 영수증 사진 첨부) / PC: `/vehicle-logs` 목록·필터·엑셀 다운로드 |
| Core Value | 운전자 입력 부담 최소화 + 회계가 「업무용승용차 운행기록부」 양식 그대로 받아 그대로 제출 가능 |

## Context Anchor

| Key | Value |
|-----|-------|
| WHY | 업무용 승용차 비용 손비처리 시 「운행기록부」 작성·보관 의무 (법인세법 시행규칙 별지 제29호의5). 종이 작성·집계 부담 제거 |
| WHO | 1차: 회사 차량 운전자 전 직원 (영업·관리·생산), 2차: 회계담당자(PC 다운로드·제출), 3차: 임원진(현황 모니터링) |
| RISK | 동일 차량 운행이력 누락 시 odometer 자동채움 부정확 → 사용자 수정 가능하게 하고 직전 기록 표시 / 영수증 사진 용량 → 5MB 제한 + 리사이즈 |
| SUCCESS | 운전자가 모바일에서 30초 이내 등록 완료, 회계가 월별 엑셀 다운 한 번으로 제출용 양식 확보 |
| SCOPE | v1: 등록·조회·수정·삭제·엑셀 다운로드 / 차량 프리셋은 출장관리(`business_trip_vehicles`) 공유 / v1 제외: 차량별 사용비율 자동 계산, GPS 자동 거리 측정, OCR |

## 1. Requirements

### 1.1 Functional
- FR-1. 운행일지 등록 — 사용일자, 차량, 주행 전 km, 주행 후 km, 주유금액, 출발지, 도착지, 사용목적, 영수증사진
- FR-2. 주행거리(km) = 주행 후 - 주행 전 자동 계산 (실시간 표시)
- FR-3. 직전 동일 차량 기록의 "주행 후 km"를 신규 등록 시 "주행 전 km"에 자동 채움 (수정 가능)
- FR-4. 사용자 정보(부서/성명/직급)는 로그인 세션에서 자동 채움
- FR-5. 영수증 사진 1장 첨부 옵션 (Supabase Storage)
- FR-6. 모바일 목록: 내 기록 최신순, 카드 형태 + 추가(+) FAB
- FR-7. PC 목록: 차량/사용자/기간 필터, 테이블 + 행 클릭 상세
- FR-8. PC 엑셀 다운로드 — 「업무용승용차 운행기록부」 별지 양식 그대로 (사업연도 헤더 + 차량 헤더 + 운행내역 테이블)
- FR-9. 본인은 자기 기록 수정/삭제 가능, 관리자/회계는 전체 수정 가능
- FR-10. 차량 프리셋은 `business_trip_vehicles` (출장관리)와 공유 — 한곳에서 관리

### 1.2 Non-Functional
- NFR-1. 모바일 입력 30초 이내 (필수: 차량/주행후/출발지/도착지/사용목적)
- NFR-2. 직전 odometer 조회는 인덱스(`vehicle, use_date DESC`)로 50ms 이내
- NFR-3. 영수증 사진은 Supabase Storage `documents/vehicle_logs/{id}.{ext}`, 5MB 제한
- NFR-4. 엑셀은 openpyxl, 양식 별지서식 그대로 (제목/사업연도/법인명/사업자번호 헤더 포함)
- NFR-5. ALL HISTORY 로깅 (append_history_log 패턴 — 등록/수정/삭제)

### 1.3 Permissions
- 메뉴 키: `vehicle_log`, 그룹: `공통메뉴`
- 영업부 / 관리부 / 생산부 / 임원진: `rw` (전 직원이 운전 가능)
- admin: 전체 수정·삭제 / 일반 사용자: 본인 기록만 수정·삭제

## 2. Success Criteria

| # | Criteria | Verification |
|---|----------|--------------|
| SC-1 | 모바일 `/m/vehicle-logs`에서 1탭으로 폼 진입 + 차량 선택 시 직전 주행후 km 자동 채움 | 모바일 화면 + DB 더미 1건 |
| SC-2 | 주행 후 km 입력 시 주행거리 실시간 자동 계산 표시 | 폼 동작 확인 |
| SC-3 | PC `/vehicle-logs` 목록 진입, 차량/사용자/기간 필터 동작 | 브라우저 확인 |
| SC-4 | 엑셀 다운로드 결과가 「업무용승용차 운행기록부」 별지 양식과 동일한 구조 | 다운로드 파일 비교 |
| SC-5 | 영수증 사진 첨부/조회 정상 동작 (Supabase Storage URL) | 업로드 후 모바일/PC 양쪽 표시 |
| SC-6 | 출장관리 차량 프리셋 변경 시 운행일지 차량 선택지도 즉시 반영 | 관리자 설정 후 폼 재진입 |
| SC-7 | 등록/수정/삭제 시 history_logs 기록 남음 | DB 조회 |

## 3. Risks
- R1. 직전 odometer 자동채움 정확도 — 다른 운전자가 같은 차를 먼저 등록 안 하면 차이 발생. → "직전 기록: 2026-04-25 12,345km" 안내 표시 + 항상 수정 가능
- R2. 영수증 사진 용량 — 5MB 제한 + 클라이언트 리사이즈(canvas 1280px) 적용
- R3. 사업자/법인 정보 — 엑셀 헤더에 들어갈 ㈜매그나텍 / 408-81-68519 는 config 상수로 고정
- R4. 차량 프리셋 공유 — 출장관리에 "개인차량/대중교통/기타" 항목이 있는데 운행일지엔 부적합. → 운행일지 폼에서 "회사차량(쏘렌토 9539, 스타리아 3417, 포터 8804) + 기타" 만 화이트리스트 필터
