- **Created**: 2026-04-06

---

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 부서 간 정보 단절 — 영업에서 납품일정 잡아도 생산팀이 알 수 없고, 데이터만 쌓일 뿐 실무에 도움이 안 됨 |
| **Solution** | 주요 업무 이벤트 자동 알림 트리거 + 대시보드 피드 전환 + 카카오워크 연동 |
| **기능·UX 효과** | 내일 납품인데 몰랐다 → 부서별 맞춤 알림으로 업무 누락 제로 |
| **핵심 가치** | 47명 전 직원이 자기 업무에 필요한 정보를 적시에 받아 의사결정 속도 향상 |

## Context Anchor

| 항목 | 내용 |
|------|------|
| **WHY** | 부서 간 정보 단절로 납품·생산 일정 누락 빈번. 기존 알림은 입고지연 1건만 작동하여 사실상 사용 안 됨 |
| **WHO** | 영업팀(납품일정), 생산팀(생산지시), 관리부(자재·입고·서류), 전 직원(공지·일정) |
| **RISK** | 알림 과다로 무시되는 현상(알림 피로), 카카오워크 API rate limit |
| **SUCCESS** | ①납품일정 알림 수신율 100% ②대시보드 피드에서 오늘 할 일 3초 내 파악 ③카카오워크 동시 발송 |
| **SCOPE** | ERP 내부 알림 + 카카오워크 채널. 이메일·SMS 제외 |

## 1. 현황 분석

### 1.1 기존 인프라 (활용 가능)

| 구성요소 | 파일 | 상태 |
|----------|------|------|
| DB 모델 (notifications) | `modules/models/misc_entities.py:109-120` | ✅ 사용 가능 |
| API 라우트 (CRUD) | `routes/notification.py` | ✅ 사용 가능 |
| 유틸 함수 (개인/그룹/전체) | `modules/notification_utils.py` | ✅ 사용 가능 |
| 벨 아이콘 + 뱃지 (30초 폴링) | `templates/base.html`, `static/js/notification-badge.js` | ✅ 사용 가능 |
| 알림센터 페이지 | `templates/notification_center.html` | ✅ 사용 가능 |
| 카카오워크 연동 | `modules/kakaowork_notifier.py` | ✅ 사용 가능 |

### 1.2 현재 문제점

1. **트리거 부재**: 입고지연 알림 1건만 작동, 나머지 업무 이벤트 알림 없음
2. **부서 간 단절**: 영업이 납품일정 잡아도 생산팀이 알 방법 없음
3. **대시보드 비효율**: 정보가 분산되어 오늘 뭘 해야 하는지 한눈에 안 보임
4. **카카오워크 편중**: 생산완료/계약등록/출장은 카카오워크만 발송, ERP 내부 알림 없음
5. **알림 유형 미분류**: noti_type이 'system' 하나뿐

### 2.3 대시보드 피드 재설계

현재 대시보드의 문제: KPI 숫자 + 칸반 + 캘린더 + 전광판 + 타임라인이 혼재

**변경 방향**:
- **상단**: KPI 요약 카드 (현행 유지, 간결하게)
- **중앙**: **업무 피드** — 최근 알림 + 히스토리 로그를 시간순 통합 피드로 표시
  - 내 부서 관련 알림 우선 표시
  - 이슈/긴급은 상단 고정
  - 각 항목에서 해당 화면으로 바로 이동 가능 (link)
- **우측 사이드**: 미니 캘린더 + 오늘 연차/출장 (현행 유지)
- **전광판**: 알림 피드로 통합, 별도 관리자 전광판 제거

## 3. 기술 범위

### 3.1 백엔드

| 작업 | 설명 |
|------|------|
| 알림 트리거 서비스 | 각 업무 이벤트 발생 지점에 알림 생성 코드 삽입 |
| 스케줄러 작업 추가 | D-7, D-1, 만료 임박 등 시간 기반 알림은 APScheduler cron job |
| 듀얼 채널 디스패처 | ERP 알림 + 카카오워크 동시 발송하는 통합 함수 |
| notification_utils 확장 | 부서별 발송 + noti_type 분류 지원 |
| 대시보드 피드 API | 알림 + 히스토리 로그 통합 피드 API |

### 3.2 프론트엔드

| 작업 | 설명 |
|------|------|
| 알림 드롭다운 패널 | 벨 아이콘 클릭 시 최근 알림 10건 드롭다운 |
| 토스트 알림 | 새 알림 수신 시 우하단 토스트 표시 (5초 자동 닫힘) |
| 대시보드 피드 UI | 통합 피드 타임라인 (알림 유형별 아이콘/색상) |
| 알림센터 개선 | 유형별 필터, 읽음/안읽음 필터 |

### 3.3 변경하지 않는 것

- DB 스키마: 기존 notifications 테이블 그대로 사용 (noti_type 값만 다양화)
- 카카오워크 API 연동 방식: 기존 kakaowork_notifier.py 구조 유지
- 알림 설정/개인화: 이번 범위에서 제외 (전체 수신)
- WebSocket: 30초 폴링 유지 (47명 규모에 충분)

## 4. 구현 전략

### Phase 1: 알림 트리거 확대 (핵심)
1. 듀얼 채널 디스패처 함수 작성 (`dispatch_notification`)
2. 납품 관련 알림 트리거 삽입 (D-7, D-1, 초과, 일정변경)
3. 생산/자재 알림 트리거 삽입
4. 서류/하자보증/인증서 알림 스케줄러 등록
5. 기존 카카오워크 전용 알림을 듀얼 채널로 전환

### Phase 2: 알림 UX 개선
1. 벨 아이콘 드롭다운 패널 구현
2. 토스트 알림 구현
3. 알림센터 필터 기능 추가

### Phase 3: 대시보드 피드 전환
1. 통합 피드 API 구현 (알림 + 히스토리 로그)
2. 대시보드 레이아웃 재설계
3. 전광판 → 피드 통합

## 6. 리스크

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 알림 과다 → 피로감 | 중 | 중요도별 분류, 이슈/긴급만 토스트, 나머지는 피드만 |
| 카카오워크 API rate limit | 중 | 스케줄러 알림은 배치 처리, 개별 알림은 기존 패턴 유지 |
| 대시보드 성능 저하 | 중 | 피드 API 페이지네이션 + 캐시 |
| 기존 카카오워크 알림과 중복 | 저 | 기존 코드를 듀얼 디스패처로 교체 (중복 제거) |

## 7. 비기능 요구사항

- 알림 생성은 non-blocking (실패해도 원래 업무 흐름 중단 안 함)
- 30초 폴링 주기 유지 (47명 규모에 적합)
- 알림 보존 기간: 90일 (이후 자동 삭제 스케줄러)
- 히스토리 로그 기존 구조 유지 (알림과 별개)
