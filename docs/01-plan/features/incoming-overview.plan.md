# Plan: incoming-overview (발주/입고현황)

## Executive Summary

| 관점 | 내용 |
|------|------|
| Problem | 생산팀이 "지금 뭐가 발주됐고 뭐가 들어올 예정이고 뭐가 들어왔는지" 파악하려면 발주관리/입고관리/가공발주 3개 메뉴를 따로 열어야 함 |
| Solution | PO 품목 ↔ Receiving 품목 join 데이터를 한 화면에서 품목 단위로 잔량/예정일/상태 표시 |
| Function/UX | 생산부 그룹 신규 메뉴(`발주/입고현황`). PC 테이블 + 모바일 카드 리스트, 4개 KPI + 상태 탭 필터 |
| Core Value | 생산팀이 자재 도착 시점을 한눈에 파악 → 작업 일정 선조정 가능 |

## Context Anchor

| Key | Value |
|-----|-------|
| WHY | 발주/입고/가공발주가 서로 다른 메뉴에 분산되어 생산팀이 자재 도착 추적이 어려움 |
| WHO | 1차: 생산부, 2차: 관리부(발주 처리), 임원진(현황 모니터링) |
| RISK | 대량 PO/Receiving join 시 N+1 쿼리 → joinedload로 방어, 100건 이상 페이지네이션 필요 |
| SUCCESS | 한 페이지에서 미입고/지연/입고예정/완료 품목 분류 + 잔량 정확도 100% |
| SCOPE | PO 기반 입고 흐름만(가공발주는 v2). 읽기 전용 — 입고 처리는 기존 화면 사용 |

## 1. Requirements

### 1.1 Functional
- FR-1. 품목 단위로 발주량/입고량/잔량/예정입고일/상태 표시
- FR-2. 상태 분류: 미입고(입고량=0), 부분입고(0<입고량<발주량), 입고완료(잔량=0), 지연(예정일<오늘 AND 잔량>0)
- FR-3. 4개 KPI 카드: 미입고 / 지연 / 7일내 예정 / 오늘 입고
- FR-4. 필터: 상태탭(전체/미입고/부분/완료/지연), 검색(품목명/현장/거래처/PO번호), 기간
- FR-5. PO 행 클릭 시 PO 상세로 이동
- FR-6. PC + 모바일 모두 지원

### 1.2 Non-Functional
- NFR-1. 100건 이상 시 서버 사이드 페이지네이션
- NFR-2. joinedload로 N+1 방지
- NFR-3. 기존 UI 톤(po_list.html 스타일) 100% 일관성
- NFR-4. 모바일 ListPage 컴포넌트 패턴 재사용

### 1.3 Permissions
- 생산부: `r` (읽기)
- 관리부: `r` (참조)
- 임원진: `r`
- 메뉴 키: `incoming_overview`, 그룹: `생산부`

## 2. Success Criteria

| # | Criteria | Verification |
|---|----------|--------------|
| SC-1 | `/production/incoming` 접근 시 KPI 4개 + 테이블 렌더링 | 브라우저 확인 |
| SC-2 | 모바일 `/m/incoming` 진입 가능, More 메뉴에 추가됨 | 모바일 화면 확인 |
| SC-3 | 잔량 = 발주량 - 입고량 일치 | 샘플 PO로 검증 |
| SC-4 | 지연 건이 빨간 뱃지로 최상단 정렬 | 정렬/스타일 확인 |
| SC-5 | 생산부 사용자 메뉴 진입 가능 | 권한 시드 확인 |

## 3. Risks
- R1. 가공발주(processing_order)는 별도 흐름 — 본 페이지 v1 제외
- R2. 거래처별/현장별 그룹핑은 v2 (디자인 깔끔하게 유지 위해 행 단위만)
