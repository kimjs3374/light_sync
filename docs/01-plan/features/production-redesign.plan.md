# Production Redesign Plan

## Executive Summary

| Perspective | Description |
|-------------|-------------|
| Problem | 현재 생산관리가 관리자 조망용으로 설계되어 4단계 depth(목록→현장→품목→공정), 모달 수량입력, 860px 고정 테이블 등 현장 작업자가 실제로 쓰기 어려운 구조. 작업자는 "오늘 뭐 해야 됨? 몇 개 했음?" 이 2개만 빠르게 처리하고 싶음 |
| Solution | 생산관리 전체를 작업자 중심 카드형 UI로 재설계. 공정 단위 플랫 리스트 + 인라인 수량입력 + 모바일 최적화. 관리자 조망은 기존 display 활용 |
| Function UX Effect | 공정 상태변경·수량입력이 1클릭/1탭. 현장→품목→공정 탐색 불필요. 카드형 레이아웃으로 모바일/태블릿에서 가로스크롤 없음 |
| Core Value | 공장 작업자의 ERP 입력 저항 제거 → 실시간 생산 데이터 수집률 향상 → 정확한 납기 예측 + 현황판 자동 갱신 |

## 1. Background

### 현재 구조의 문제점

| # | 문제 | 현재 | 작업자가 원하는 것 |
|---|------|------|-------------------|
| 1 | 진입 depth 4단계 | 목록→현장클릭→스크롤→공정 찾기 | "내 진행중 공정" 바로 보기 |
| 2 | 현장 단위 페이지 | 한 현장의 모든 품목/공정 한꺼번에 | 특정 공정만 관심 (PCB 담당자는 PCB만) |
| 3 | 수량입력이 모달 | 상세→모달→입력→저장 (4클릭) | 테이블/카드에서 바로 숫자 치고 엔터 |
| 4 | 모바일 불가 | min-width:860px 테이블 | 태블릿/폰에서 수량입력 |
| 5 | 오늘 현황 없음 | 전체 공정 리스트만 | 오늘 생산 수량, 완료 공정 요약 |
| 6 | 담당자 개념 없음 | 현장 기준 전체 표시 | 내 담당 공정만 필터 |

### 유지할 것
- `production_logic.py` — 공정 템플릿, 상태 계산, 의존관계 로직 (검증 완료, 매그나텍 프로세스 정확)
- `production_display.html` — TV 전사 현황판 (별도 용도, 변경 불필요)
- `ProductionProcess`, `ProductionDailyLog` 모델 (DB 구조 유지)
- `production_actions.py` — 핸들러 로직 재활용

## 2. Goal
- 생산관리 UI를 **작업자 중심 카드형**으로 전면 재설계
- 공정 상태변경 + 수량입력을 **1액션**으로 처리
- **모바일/태블릿** 완벽 지원 (공장에서 사용)
- 관리자 조망은 **기존 display + 필터/정렬**로 해결

## 3. Scope

### In Scope

#### A. 생산관리 메인 (`/production`) — 카드형 리스트 (기존 목록+상세 통합)
- **뷰 모드 3가지**: 공정별 / 현장별 / 오늘 생산
- **공정별 뷰** (기본): 전체 공정을 상태별로 그룹핑 (진행중 → 대기 → 완료)
  - 카드 1장 = 공정 1개 (현장명, 모델, 수량, 진척률, 인라인 수량입력)
  - 필터: 상태, 카테고리(투광등/가로등주/조명타워), 현장명 검색
- **현장별 뷰**: 기존 production_detail 대체. 현장 선택 → 해당 현장 품목/공정 카드
- **오늘 생산 뷰**: 오늘 일일로그가 있거나 진행중인 공정만. 오늘 합계 표시

#### B. 공정 카드 인터랙션
- **토글 스위치**: OFF(대기) → ON(진행중) → 완료 체크 — 의존관계 자동 검증
- **인라인 수량입력**: 카드 하단에 `[오늘 수량: ___]` 입력란. 엔터/blur 시 AJAX 저장
- **프로그레스 바**: 누적수량/목표수량 시각화
- **자재 상태 뱃지**: 자재대기중이면 빨간 뱃지 + 토글 비활성화

#### C. AJAX 기반 실시간 저장
- 모든 조작(상태변경, 수량입력)은 AJAX POST → JSON 응답
- autosave dot 피드백 (idle → saving → saved → error)
- 페이지 새로고침 없음

#### D. 모바일 최적화
- 카드형 레이아웃 (가로스크롤 없음)
- 터치 친화적 토글/입력
- 반응형: 모바일 1열, 태블릿 2열, 데스크탑 3열

### Out of Scope
- 작업자별 로그인/담당자 배정 (향후 확장, 현재는 부서 기준)
- 공정 템플릿 UI 편집 (production_logic.py 코드 기반 유지)
- QC 체크포인트 (별도 PDCA)
- 사이클타임 분석 대시보드 (별도 PDCA)

## 4. Success Criteria
- 수량입력까지 **최대 2클릭** (기존 4클릭 → 50% 감소)
- 모바일에서 **가로스크롤 없이** 전체 기능 사용 가능
- 페이지 로딩 후 공정 상태변경·수량입력 시 **페이지 새로고침 0회** (전부 AJAX)
- 기존 생산 데이터 100% 호환 (DB 변경 최소화)

## 5. Technical Approach

### 5.1 라우트 구조

| 기존 | 변경 | 비고 |
|------|------|------|
| `GET /production_management` | `GET /production` | 카드형 통합 메인 |
| `GET /production_management/<id>` | 제거 (메인에서 현장별 필터로 대체) | |
| `POST /production_management/<id>` | `POST /api/production/...` | AJAX API로 전환 |
| `GET /production/display` | 유지 | TV 현황판 |

### 5.2 API 엔드포인트 (신규/변경)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/production` | 카드형 메인 페이지 (HTML) |
| GET | `/api/production/processes` | 공정 목록 JSON (필터/정렬) |
| POST | `/api/production/process/<id>/status` | 공정 상태 변경 |
| POST | `/api/production/process/<id>/daily-log` | 일일 수량 입력 |
| POST | `/api/production/sync` | 공정 동기화 (기존 유지) |

## 6. Implementation Order
1. **API 엔드포인트** — 상태변경/수량입력 AJAX API (기존 핸들러 재활용)
2. **카드형 메인 템플릿** (`production.html`) — 3가지 뷰 + 필터 + 카드 그리드
3. **카드 인터랙션 JS** — 토글, 인라인 수량입력, autosave, 프로그레스 바
4. **라우트 통합** — 기존 목록/상세 → 새 메인으로 redirect
5. **모바일 반응형** — CSS 그리드 조정 + 터치 최적화
6. **사이드바 메뉴** — 생산관리 메뉴 endpoint 변경
